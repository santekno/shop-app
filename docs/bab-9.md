## Decisions

No ADR in this chapter: no API, data or deployment-model change. The web decisions are recorded in `docs/web/README.md` (Bab 9 section) and in the code's comments.

- **React Router v7 in data mode, without the framework** (`apps/web/src/app/App.tsx`, `app/routes.tsx`): `createBrowserRouter` and `<RouterProvider>` give `lazy`, `ErrorBoundary`, `HydrateFallback`, `useNavigation` and `ScrollRestoration` without framework mode's build plugin and file conventions, since Bab 11 moves the storefront to Next.js. No loaders: TanStack Query owns server data. Version 7.18.4 at the orchestrator's request, although 8.5.0 was out.
- **One layer retries** (`apps/web/src/lib/query-client.ts`): the API client already retries a GET twice where retrying helps (network failure, timeout, 502/503/504), so queries use `retry: false`; both layers retrying would mean up to 12 requests and about a minute of "Memuat…" against an API that is down, and retries of errors that never pass (404, 400). Mutations are never retried. `staleTime` is 30 s (5 minutes for categories), not TanStack's 0. Every `queryFn` passes TanStack's `signal` to the client, so a request nobody waits for is aborted.
- **The URL is state:** the category (`kategori`), search (`q`) and sort (`urut`) are read from the search params as untrusted input and written back (`features/catalog/catalog-filters.ts`); the cursor stays out of the URL. A product is `/produk/:slug`; the back link returns to the list it came from.
- **Focus on navigation** (`app/useRouteFocus.ts`, `hooks/useLateHeadingFocus.ts`): the focus moves to the new page's `<h1>`, or back to the card of the product the buyer came from; a heading that arrives with its data takes over from `<main>`; a change of query string leaves the focus on the control in use.
- **Infinite scroll:** `useInfiniteQuery` with an IntersectionObserver sentinel (`hooks/useOnVisible.ts`); "Muat lebih banyak" stays for keyboards and where the observer is missing; Bab 8's same-cursor guard moved into `getNextPageParam`.
- **Optimistic add changes only what is on screen** (`features/cart/hooks/useAddToCart.ts`, `features/cart/optimistic-cart.ts`): the header count, the subtotal and an existing line's quantity move at the click; a variant not yet in the cart gets no guessed line. The API's cart replaces the guess; on an error the snapshot comes back and the message says why (409 `INSUFFICIENT_STOCK`, `QUANTITY_LIMIT`, `CART_FULL`, `VARIANT_UNAVAILABLE`). One queue for every add, and a refetch after the last one, so the cache ends with the server's word.
- **Tokens stay in memory in Bab 9** (`features/cart/CartTokenProvider.tsx`, `features/auth/SessionProvider.tsx`): a reload forgets the guest cart and the session. The refresh token is not kept at all, nothing refreshes the access token, and no request sends it yet. Never `localStorage` for tokens (ADR 0005). Bab 10 builds the real storage.
- **Zod schemas live in `packages/shared`** (`src/schemas/auth.ts`), so web and mobile check the same rules, written from what the API checks (`apps/api/internal/auth/handler.go`, `password.go`): a trimmed ASCII email up to 254 characters, a password of 8 to 128 characters counted as Go counts them (code points) and not only spaces, a trimmed name up to 100 characters. The common-password list stays on the server and arrives as a field error. `satisfies z.ZodType<RegisterRequest>` ties each schema to the contract's type; `zod.ts` sets `jitless` for the CSP (above).
- **The API's errors land on the form** (`lib/api-form-errors.ts`): `VALIDATION_FAILED` details go to their fields in Indonesian, `EMAIL_TAKEN` to the email field, `INVALID_CREDENTIALS` as a form-level error; the first invalid field gets the focus, whether the error came from Zod or from the API; a form-level error (`FormAlert`) takes the focus itself, every time it is set.
- **Errors and the 404** (`app/RouteErrorPage.tsx`, `app/NotFoundPage.tsx`): each route has an `ErrorBoundary`; a missing product (`NOT_FOUND`) is thrown to it and shows the 404 page; each caught error is reported once, and `NOT_FOUND` is not logged, so the e2e "no console error" rule still holds.
- **Lazy routes:** the product page and the auth pages are their own chunks (`features/product/lazy.ts`, `features/auth/lazy.ts`), with a navigation progress bar and a `HydrateFallback`; React Hook Form and Zod sit in a chunk shared by the auth pages (`navigation-state`), and a second shared chunk holds `useMutation` (the auth pages and the product page), both out of the catalog's bundle.
- **Prefetch** (`features/product/hooks/usePrefetchProduct.ts`): a product's data and page chunk on a mouse hover that rests 100 ms, or on focus (keyboard, and in Chromium also a mouse press or a tap, at no extra request); no hover prefetch on touch, and nothing on a fast sweep. It calls `queryClient.query`, the newer name of `prefetchQuery`, which TanStack Query 5.10x marks deprecated and the lint refuses.
- **Still no product photos:** the catalog, product page and cart keep Bab 8's "Belum ada foto" placeholder; Bab 11 adds the photos.
- **Tests:**
  - `apps/web/src/test/render.tsx` renders components under a memory router and a test `QueryClient`; the fake API gained cart and auth fixtures;
  - `e2e/support/global-setup.ts` runs once before the suite: it clears the rate-limit counters (`goshop:rl:*` in the Compose Redis) and makes sure the verified buyer the login specs use exists (`e2e/support/accounts.ts`);
  - `e2e/tests/dev-warnings.spec.ts` walks the Bab 9 flows in the Vite dev server and allows only the expected 404 in the console.
