## Stack and structure
- Go 1.26+ (`.go-version`), module `github.com/santekno/shop-app/apps/api`. Binaries in `cmd/api` and `cmd/worker`.
- Router: chi. Layering per feature: `internal/<feature>/{handler.go,service.go,repository.go,model.go}`. Handlers decode, validate and map errors. Services hold business rules. Repositories hold SQL. Wire dependencies by hand in `internal/app` (ADR 0004); `cmd/api/main.go` only calls `app.Run`. No DI framework.
- Database: PostgreSQL through `github.com/santekno/sdk/sqlx` with the `github.com/jackc/pgx/v5/stdlib` driver. Queries are generated by sqlc in `database/sql` mode into `internal/db/sqlc`. Migrations use golang-migrate in `migrations/` and are always reversible.
- Use santekno/sdk for every concern it covers, pinned to an explicit released version with no `replace`, starting with v0.2.0, released 2026-10-22 (tag v0.2.0, commit 97a873a). Use `go get github.com/santekno/sdk@v0.2.0`, never `@latest`:

  | Concern | Package |
  |---|---|
  | config | `configx` |
  | logging | `logx` |
  | errors | `errx`: typed errors with code, message, details and HTTP status. It has no HTTP writer. |
  | HTTP error body | `middleware/chi` `DefaultErrorWriter` writes `{"error":{"code","message","details?"}}` from an `errx.AppError` (v0.2.0). Use it for handler errors too, and for chi's `NotFound`/`MethodNotAllowed`. |
  | middleware | `middleware/chi`: `RequestID`, `Logger`, `Recovery`, `Tracing`, `JWTAuth` + `ClaimsFromContext` (v0.2.0) |
  | validation | `validx` |
  | health checks | `healthx`; set `Handler.HideErrors` outside development (v0.2.0) |
  | password hashing | `hashx` |
  | tokens | `jwtx` |
  | rate limiting | `ratelimitx`: a nested module with no tag yet, pinned by pseudo-version (see `docs/sdk-gaps.md`) |
  | Redis | `redisx` |
  | money | `moneyx` |
  | IDs | `uuidx.NewV7` (v0.2.0) |
  | storage | `storagex` interface; the S3 implementation with presign is GoShop's own (Bab 6) |
  | LLM | `aix` |
  | tracing, metrics | `tracex`, `metricx` interfaces; the exporters are GoShop adapters (Bab 19) |

  If sdk lacks something, write a small adapter and add a row to `docs/sdk-gaps.md` (you own it).
- Config comes only from env vars, and the server listens on `$PORT` when set. Shut down gracefully on SIGTERM.
- Dockerfiles: multi-stage, repo root as build context, distroless or alpine runtime, non-root user, no secrets baked in.

## How you work
- Implement exactly what the chapter's articles teach, in article order. Commit per article: `feat(bab-N/artikel-NN): <what>`. Conceptual articles need no commit.
- Keep functions small and named for what they do. Comment only the why, not the what.
- Before reporting, run `make build lint docker-build` and fix everything it reports.
- Do not write unit tests. List every exported function and handler you added or changed, with its expected behaviour and edge cases, so test-engineer can cover them.
